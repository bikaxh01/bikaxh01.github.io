Building a Coding Agent from First Principles (Part 1)

3 minutes read •

  • ai
  • agents
  • langgraph
  • engineering

We’ve all seen the rise of powerful AI coding assistants recently—tools like Claude Code, Codex, and the Pi agent are fundamentally changing how we write software. But under the magic, what exactly is a coding agent?

Strip away the hype, the complex sandbox environments, and the advanced context compression algorithms, and you are left with something surprisingly simple: a coding agent is just an LLM given a set of tools, iterating in a loop until a task is finished.

Everything else is just optimization.

In this article, we’re going back to first principles. We will build a conversational, agentic coding assistant using LangGraph and LangChain. Our agent will interact with a local sandboxed directory, read files, run commands, and edit code autonomously.

The Core Loop: Reasoning and Acting

The heart of our agent is a state machine. The agent loops between reasoning (the LLM deciding what to do) and acting (executing the chosen tools).

When a user asks for a feature or a bug fix, the LLM looks at the available tools, picks the right one to gather context or make changes, and receives the output. It then evaluates if the task is complete. If not, it picks another tool.

Here is what the architecture looks like in LangGraph:

graph TD
    __start__((START)) --> llm_node
    
    llm_node(LLM Node) --> condition{Should Continue?}
    
    condition -- "Yes (Call Tools)" --> tools(Tools Node)
    condition -- "No (Finished)" --> __end__((END))
    
    tools --> llm_node

Arming the Agent: Available Tools

An LLM is only as good as the tools it has access to. For a coding agent to be effective, it needs highly specific tools to manipulate the workspace efficiently.

We equipped our agent with the following core capabilities:

  • ls(path): Lists the contents of a directory. Used to explore the structure of the workspace.
  • read(path): Reads the contents of a specific file.
  • find(pattern, path): Locates files by name or using glob patterns.
  • grep(pattern, path): Searches for specific text or regular expressions across multiple files.
  • write(path, content): Creates a brand new file or completely overwrites an existing one.
  • edit(path, old_string, new_string): Modifies an existing file using an exact substring search-and-replace. This is safer and more precise for LLMs than line-number based editing.
  • bash(command): Executes a shell command inside the workspace (e.g., running tests, compiling code, or installing dependencies).

Seeing It in Action

With LangGraph managing the state and our tools firmly in place, the agent can maintain persistent in-memory checkpoints for multi-turn conversations.

Here’s how you can run this basic implementation locally:

  1. Set your environment variables in .env (like your OpenAI or Anthropic API keys).
  2. Run the agent using uv (a fast Python package installer and resolver):
    uv run main.py
  3. Type your requests into the terminal. The agent will execute tools automatically and stream its responses.
  4. Type exit to quit the interactive loop and view the session summary.

What’s Next?

We’ve covered the absolute basics: give an LLM some tools and put it in a loop. But this naive approach quickly runs into limitations in the real world.

What happens when the output of grep is too large for the context window? How do we prevent the agent from running destructive bash commands? How do we help it navigate a massive monorepo without getting lost?

In Part 2, we will take this foundational agent and improve it. We’ll dive into the critical optimizations that make production-grade coding agents actually useful: context window management, output truncation, safer sandboxing, and self-correction mechanisms.
